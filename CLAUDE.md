# Enshrouded interactive map

Migration of a working prototype into a real app. The plan (approved, in French) is in `docs/PLAN.md`; follow it step by step.

## Current state
- Functional rules of every screen (accounts, teams, map, workshop, lore, enemies, character formulas, recommendations, game settings) are in `docs/RULES.md`: update it when a rule changes.
- The migration of the original prototype (a single `index.html` + a stdlib `server.py`) is finished and the prototype was removed (it stays in the git history before commit "Remove legacy prototype").
- `artifacts/map/`: generated map data (tiles/{z}/{x}_{y}.jpg, icons/, biomes.png, overview.jpg, map-data.json + resources.json). Must not go into git.
- `pipeline/`: offline extraction scripts. They need the game install, `emm.exe` and ~6.5 GB of raw data that only exist on the Windows PC (D:\DEV\enshrouded_extract). They cannot run here; only edit them. `build_data.py` writes `map-data.json` + `resources.json` (reference counts: see `pipeline/README.md`).

## Accounts (decided later)
- No public sign-up. On an empty database the first visit must create the first account (`POST /auth/setup`, refused once any account exists and unless the caller sends the setup token: `SETUP_TOKEN`, or a random one printed once in the API log at start; the dialog cannot be dismissed). After that only a logged-in user can create a single-use invitation (`POST /auth/invitations`, valid `INVITATION_MINUTES`=20), sent as `<site>/#invite=<token>` (fragment, so it is never logged). The token is stored hashed; accepting it creates the account atomically.

- Passwords: users change their own (`POST /auth/password`, current password required, other sessions revoked). The first account (`users.first_account = true`, `is_admin` in the API) generates single-use reset links for others (`/auth/password-resets*`, `#reset=<token>`, 20 min); a link replaces the previous one for the same user. If the first account is locked out: `python -m app.cli reset-password USERNAME` in the api container. Password fields have a show/hide button.

## Teams, profile and access (added after the first release)
- Without an account the page shows only the login dialog (no map, not dismissible). nginx serves the map files (`tiles`, `icons`, `biomes.png`, `overview.jpg`, `map-data.json`, `resources.json`) only with a valid session: `auth_request` -> `GET /api/v1/auth/check`. `ng serve` does not protect them. `map-data.json` is loaded after login (`SessionService.enter`).
- Teams (`backend/app/api/v1/team.py`, `TeamStore`): one team per player, the creator is the owner (renames, disbands, hands the team over with `POST /team/owner`). Any member adds an existing player (`POST /team/members`), removes another one (not the owner) or creates an invitation link; that link is an account invitation (`invitations.team_id`) whose new account joins the team. Leaving hands the team to the longest-standing member. Halo on the map: blue = only I marked it, violet = me and some (not all) of the others (so only from 3 members), orange = other members did and I did not, green = every member did (no team or a team of one: green when I marked it); the map has a foldable colour legend (`progress-legend.ts`, state in `localStorage` key `legend`); a loot stack's icon is orange while one of its items waits on me, blue when I am alone on all that are marked; the popup lists who did. The others' marks are refetched every 60 s and when the tab comes back.
- Profile menu (invite, team, password, delete account, logout). Deleting an account (`POST /auth/delete-account`, password required) erases its progress; the first account cannot be deleted. Password fields have a confirmation field. The left menu can be hidden and placed on the left, on top, or automatically (portrait = top), remembered per device.
- Loot: cosmetics (item debug name `Vanity_*`, 105 of the 179 former "unique" items) have their own violet category `cosmetic` (pipeline: `build_resources.special_loot`, icon `cosmetic.svg`). Clicking a loot marker (unique, cosmetic, collectible) lists every shown loot marker within 3 m in one popup, each with its mark button. Mark ids of cosmetics changed from `unique:x:z` to `cosmetic:x:z`. The local `artifacts/map` was patched the same way; re-run the pipeline on the Windows PC to regenerate it.
- The first account can delete another account (profile menu > Administration, `admin-dialog`, which also holds the reset links): `DELETE /auth/users/{id}` (admin only, not itself, never the first account), same cascade as "delete my account" plus `leave_team`; UI in the admin dialog.
- Landmarks (`start`, `fastTravel`): icon 1.4x bigger, above the others, never faded when marked (`LANDMARK_CATS` in `map-view.ts`); their halo still applies.
- Passkeys (WebAuthn, py_webauthn): optional, on when `WEBAUTHN_RP_ID` + `WEBAUTHN_ORIGIN` are set (https and one host name; `/auth/me` returns `passkeys_enabled`). Alternative login next to the password; managed from Profile > Passkeys (`passkey-dialog`), "Use a passkey" button on the login screen. Table `passkeys`, routes `/auth/passkeys/*` (`backend/app/api/v1/passkeys.py`), challenges in memory (`app/core/passkeys.py`, single worker). Playwright runs on `http://localhost:4200` with a virtual authenticator.

## Decisions taken with the user
- Stack: FastAPI + SQLAlchemy 2 + Alembic + Pydantic v2 (uv), Angular standalone + signals, docker compose (nginx-unprivileged web + api), SQLite in a volume, code portable to PostgreSQL/MySQL via `DATABASE_URL`.
- Exposure: LAN only, behind the user's own reverse proxy (it terminates TLS).
- Start from an empty database (no migration of prototype accounts).
- Apply security best practices (see plan step 2/4/5), run `/security-review` and `/code-review` at the end.
- Talk to the user in French.
- Visual identity ("Codex of the Shroud", redesign of 2026-11-09): tokens in `frontend/src/styles.css` (`--bg/--panel/--gold/--accent` = cold blue-slate ground, bronze lines, ember only for what is active/open; `--display` IM Fell English for titles, `--display-sc` IM Fell English SC for labels (small capitals, never all caps), `--ui` Alegreya Sans for text; fonts self-hosted from `@fontsource/*` through the `/fonts` asset globs of `angular.json`, CSP `font-src 'self'`). Shared look of every screen but the map: `workshop/workshop.css` (global, scoped by `app-workshop, app-lore, app-enemies, app-skills, app-build, app-equipment, app-game`): `--mist` background, index tabs, plates with two bronze corners, diamond on the rule under `h2`, lit ember edge on the open item. Map: mist vignette (a gradient, not a blurred shadow), popups as plates. Performance rule learned the hard way: no `background-attachment: fixed`, no large blurred shadows, no 60 fps animation of big gradients (the login backdrop drift uses `steps()`): they made the e2e suite 4x slower in headless Chromium.
