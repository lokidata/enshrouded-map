# Deploying with Portainer

The **Publish images** workflow builds, scans, pushes and signs two images on every push to `main` and on every `v*.*.*` tag:

- `ghcr.io/lokidata/enshrouded-map-api`
- `ghcr.io/lokidata/enshrouded-map-web`

Tags: `latest` (main or newest release), `sha-xxxxxxx` (one commit), `1.2.3` and `1.2` (releases). Pin `IMAGE_TAG` to a version for a stable server.

## 1. Map data on the server

The tiles and JSON are generated by the pipeline (not in git, not in the images). Copy `artifacts/map/` to a folder on the Docker host, e.g. `/srv/enshrouded-map/artifacts`. It is mounted read-only; updating the map is just replacing the files.

## 2. Create the stack

Portainer → **Stacks → Add stack**:

- **Repository**: `https://github.com/lokidata/enshrouded-map`, reference `refs/heads/main`, compose path `deploy/portainer/docker-compose.yml` (add credentials only if the repository is private), or **Web editor** with the content of that file.
- **Environment variables**:

| Variable | Required | Meaning |
|---|---|---|
| `ARTIFACTS_DIR` | yes | Folder of the map data on the host (step 1) |
| `SETUP_TOKEN` | recommended | 16-128 characters; asked for the very first account. Empty: a random one is printed in the `api` container log |
| `COOKIE_SECURE` | | `true` (default) behind HTTPS; `false` only for plain-http tests |
| `WEBAUTHN_RP_ID` / `WEBAUTHN_ORIGIN` | for passkeys | Host name players open (e.g. `carte.example.lan`) and its origin (`https://carte.example.lan`). HTTPS and a single name are required: changing it later invalidates the passkeys already registered. Empty: passkeys are off |
| `REVERSE_PROXY_IP` | behind a proxy | Address your reverse proxy connects from (client IP is trusted only from there) |
| `WEB_BIND` / `WEB_PORT` | | Published address and port (default `0.0.0.0:8080`) |
| `IMAGE_TAG` | | `latest` by default |
| `INVITATION_MINUTES` | | Lifetime of an invitation link (default 20) |
| `BACKEND_SUBNET` / `WEB_IP` | if 172.28.0.0/24 is taken | Internal network and the web container's address in it |

## 3. First start

Open the site: the first visit creates the first account with the setup code. Then invite other people from the **Inviter** button.

## Updating

Portainer → the stack → **Pull and redeploy** (tick *Re-pull image*), or change `IMAGE_TAG`. The database lives in the `db-data` volume and is migrated at start.

## Verify an image

Images are signed with GitHub's identity (keyless cosign):

```sh
cosign verify ghcr.io/lokidata/enshrouded-map-api:latest \
  --certificate-identity-regexp '^https://github.com/lokidata/enshrouded-map/' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com
```

If a package is private, add `ghcr.io` in Portainer → Registries with a token that has `read:packages`. Packages published from a public repository are public by default.

## Lost password

Users can change their password in **Compte**, and the first account can generate a reset link for them there (20 minutes, single use). If the first account is the one locked out: Portainer -> Containers -> the `api` container -> Console (`/bin/sh`, interactive), then `python -m app.cli reset-password USERNAME`.
